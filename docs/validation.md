## 証明していないこと

完了画面はスコアを設定して直接表示しており、ぶろっくを最後まで解いた展示ではありません。
実機での指の操作、音量、絵文字の字形は確認していません。
運用リポジトリにある `esm-*` と `network-events` の調査用プローブは収録していません。運用リポジトリのコミット `e8e3fa4d` でヘッドレス実行に直し、そちらで通ることを確認しましたが、モジュールの読み込みは `layout.spec.js` が確認するため重複を避けました。
退役した Cloud Run の配信は、この作業では停止していません。
公開検査は `docs/source-manifest.json` のハッシュと照合しますが、manifest 自体も同じインデックスから読みます。
そのため、検査が防ぐのは収録ファイルと manifest のずれであり、両方を同時に書き換えた変更は検出しません。

## レビューと公開時の確認

運用リポジトリで3件のテストの不整合を直してから収録しました。
遊びの数を9に合わせた件、`game.spec.js` が `DEKITA_TEST_URL` を使う件、URL指定時に検査用サーバーを別に起動しない件です。
公開前のコードレビューを受けて、次を直しました。
撮影スクリプトは、存在しないファイルへの要求を失敗として数え、画像を一時フォルダーに書いて全検査の合格後に `docs/media` へ置きます。
検査スクリプトは、http-server の起動失敗を待たずに失敗として返します。
公開検査は manifest が未ステージの場合に明示的に失敗し、回帰テストは呼び出し元の `GIT_*` 環境変数を引き継ぎません。
README の手順には、撮り直した画像を `git add` してから公開検査を実行する手順を加えました。
Python は公開リポジトリの利用者が uv を前提にしないよう、`python3` で実行する手順にしています。
公開アプリ https://dekita.ats030.workers.dev/ は、2026年10月20日にクレジット入りの版へ再配備し、公開URLでクレジットの表示と `scripts/check-cloudflare.mjs` の合格を確認しました(運用リポジトリで実行)。
公開後のコミット一致と公開状態は、作業のBeads課題に記録します。
